# S-003-T7: Test infrastructure + full coverage

**Priority:** P2 | **Status:** pending | **Blocked By:** S-003-T1, S-003-T2, S-003-T3, S-003-T4, S-003-T5

## What
Set up `node:test` framework in `test/` directory with `scripts.test` in package.json. Write tests covering all 32 identified codepaths across code-index.mjs, context.mjs, query command, and init integration.

## Why
The TRD identifies 32 testable codepaths. Tests catch regressions when codegraph updates, prevent broken init on edge cases (no JS files, partial failures), and validate the mtime-refresh logic that's hard to test manually.

## Context
- Test framework: `node:test` (built-in Node 22+, zero dependency)
- Test runner: `node --test` (discovers `test/**/*.test.mjs` by default)
- No mocking library needed — `node:test` has `mock` built in
- The 32 codepaths come from TRD Testing Strategy:
  - code-index.mjs: open success, open no-db, open error, getHandle cache hit, getHandle mtime miss, search success, search null handle, search error, callers success, callers null, callers error, impact success, impact null, impact error (14)
  - context.mjs: graduate success, graduate collision -2/-3, graduate empty slug, graduate empty body, list empty, list populated, search match, search no-match (8)
  - commands/context.mjs: TTY guard, missing title, missing body (3)
  - commands/query.mjs: no-query error, code+docs, code-only (no docs match), docs-only (no codegraph), json output, callers cap, impact cap (7)
- Integration tests need a fixture `.codegraph/` DB — create a minimal one via codegraph init on a test fixture dir
