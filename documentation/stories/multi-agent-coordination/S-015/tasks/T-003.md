# S-015-T3: Lock Primitives — acquireLock, releaseLock, withLock

**Priority:** P0 | **Status:** pending | **Blocked By:** --

## What

Add three new exported functions to `lib/tracker.mjs`: `acquireLock()`, `releaseLock()`, and `withLock()`. These provide a cross-process mutex using the O_EXCL flag on `openSync`. Include unit tests.

## Why

Every brief command that creates or updates items needs mutual exclusion to prevent races when parallel agents run in worktrees. The lock is the foundation — all subsequent tasks (atomic writes, counter, callsite wrapping) depend on it.

## Context

- `lib/tracker.mjs` currently has no locking — `writeTracker()` at line 41 does a bare `writeFileSync`
- The lock file lives at `.git/brief-id.lock` (`.git/` is shared across all git worktrees)
- To find `.git/`, use `git rev-parse --git-common-dir` — this returns the shared git dir even from worktrees
- **Critical**: `execFileSync('git', ['rev-parse', '--git-common-dir'])` returns a trailing newline — must `.toString().trim()` or all path joins break with ENOENT (eng review D6)
- Retry delay uses `Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, ms)` — in-process synchronous sleep, no forked process (eng review D3)
- Stale lock threshold: 10s. Brief commands complete in <2s; a lock older than 10s is from a crashed process.
- PID written to lock file for debugging stale locks
- Max retries: 5 × 200ms = 1 second total wait before throwing
- Non-EEXIST errors on lock acquire must rethrow immediately (not retry)
- ENOENT on release must be silently ignored (concurrent stale removal)

Design decision (TRD): O_EXCL chosen over `flock` (needs C binding) and `mkdirSync` (works but O_EXCL is canonical).

## How

**Step 1 — Add imports:**
- File: `lib/tracker.mjs`
- Add to existing imports: `openSync`, `closeSync`, `unlinkSync`, `statSync`, `renameSync` from `node:fs`
- Add: `O_WRONLY`, `O_CREAT`, `O_EXCL` from `node:fs` (or use `node:constants`)
- Add: `execFileSync` from `node:child_process`

**Step 2 — Add constants:**
```javascript
const LOCK_FILE = "brief-id.lock";
const STALE_THRESHOLD_MS = 10_000;
const MAX_RETRIES = 5;
const RETRY_DELAY_MS = 200;
```

**Step 3 — Add `gitCommonDir(projectRoot)`:**
```javascript
export function gitCommonDir(projectRoot) {
  try {
    return execFileSync("git", ["rev-parse", "--git-common-dir"], {
      cwd: projectRoot,
    }).toString().trim();
  } catch {
    return null;
  }
}
```
Returns `null` for non-git projects (fallback path).

**Step 4 — Add `acquireLock(gitDir)`:**
```javascript
export function acquireLock(gitDir) {
  const lockPath = join(gitDir, LOCK_FILE);
  for (let i = 0; i < MAX_RETRIES; i++) {
    try {
      const fd = openSync(lockPath, O_WRONLY | O_CREAT | O_EXCL);
      writeSync(fd, String(process.pid));
      closeSync(fd);
      return lockPath;
    } catch (err) {
      if (err.code !== "EEXIST") throw err;
      const stat = statSync(lockPath, { throwIfNoEntry: false });
      if (stat && Date.now() - stat.mtimeMs > STALE_THRESHOLD_MS) {
        try { unlinkSync(lockPath); } catch {}
        continue;
      }
      Atomics.wait(new Int32Array(new SharedArrayBuffer(4)), 0, 0, RETRY_DELAY_MS);
    }
  }
  throw new Error("brief: could not acquire lock — another brief process may be running");
}
```
Note: `writeSync` also needs to be imported from `node:fs`.

**Step 5 — Add `releaseLock(lockPath)`:**
```javascript
export function releaseLock(lockPath) {
  try { unlinkSync(lockPath); } catch {}
}
```

**Step 6 — Add `withLock(gitDir, fn)`:**
```javascript
export function withLock(gitDir, fn) {
  const lockPath = acquireLock(gitDir);
  try {
    return fn();
  } finally {
    releaseLock(lockPath);
  }
}
```
