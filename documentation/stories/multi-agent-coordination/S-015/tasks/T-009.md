# S-015-T9: brief next = Reserve (Increment Counter)

**Priority:** P1 | **Status:** pending | **Blocked By:** S-015-T6

## What

Change `brief next <type>` from a read-only peek to a reserve operation that increments the counter without creating any files.

## Why

CEO review D10 decided that `brief next` should reserve (increment) rather than peek (read-only). Stale peeks confuse planning agents — an agent peeks `S-015`, another peeks `S-015`, both think they own it. Gaps in numbering are cosmetic and acceptable.

## Context

Current `brief next` implementation at `cli.mjs:212-221`:
```javascript
} else if (command === "next") {
  const type = args[1] || "story";
  const { readTracker, nextId, TYPE_CONFIG } = await import("./lib/tracker.mjs");
  if (!TYPE_CONFIG[type]) {
    console.error(`Unknown type: ${type}. Valid: story, todo, decision, research, audit, bug, memory`);
    process.exit(1);
  }
  const items = readTracker(root);
  const id = nextId(items, type, root);
  console.log(id);
```

After T6, `nextId` in git repos already increments the counter via `allocateId`. So `brief next` already reserves on the git path after T6. This task verifies that behavior, adds a test, and ensures the non-git path also works correctly.

The key change: in the git path, `brief next story` now permanently allocates S-016 — calling it again returns S-017. This is the intended behavior (reserve, not peek).
