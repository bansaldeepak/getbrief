# S-015-T4: Atomic writeTracker (.tmp + renameSync)

**Priority:** P0 | **Status:** done | **Blocked By:** S-015-T3

## What

Modify `writeTracker()` in `lib/tracker.mjs` to use the atomic write pattern: write to `<path>.tmp`, then `renameSync` to the final path. Add a unit test.

## Why

A crash or kill during `writeFileSync` leaves `tracker.yaml` corrupt (partial write). The .tmp + rename pattern is POSIX-atomic — the file either has the old content or the new content, never a partial state. This is the project's standard pattern (already used in `lib/harness.mjs`).

## Context

Current `writeTracker()` at `lib/tracker.mjs:41`:
```javascript
export function writeTracker(projectRoot, items) {
  const path = trackerPath(projectRoot);
  const header = `# Project Tracker — Source of Truth
# CLI: brief create <type> <title>
#      brief update <id> <status>
#      brief generate  (regenerates PROJECT-TRACKER.md)
`;
  const body = stringify({ items }, { lineWidth: 0, nullStr: "null" });
  writeFileSync(path, header + "\n" + body);
}
```

The fix is to write to `path + ".tmp"` first, then `renameSync(path + ".tmp", path)`.

Design decision (TRD): Atomic write pattern from `coding-style.md` — "Atomic writes: write to `<path>.tmp`, then `renameSync` to final path — never write directly."

`renameSync` should already be imported after T3. If not, add it.
