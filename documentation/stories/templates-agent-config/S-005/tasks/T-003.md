# S-005-T3: Rewrite `project-memory` skill — single template, brief primary

**Priority:** P0 | **Status:** pending | **Blocked By:** --

## What
Rewrite `custom-skills/project-memory/SKILL.md` to remove all knowledge graph references. Collapse the two MEMORY.md templates into one. Make `brief` the primary read path with direct file reading as fallback.

## Why
The skill currently has ~50 lines of instructions for knowledge graph MCP tools (`knowledge_context`, `knowledge_search`, `knowledge_status`) that don't exist. It has two MEMORY.md templates — one for "knowledge graph projects" and one without. Since knowledge graph is gone, there's only one path.

## Context
- File: `custom-skills/project-memory/SKILL.md`
- The skill is used by the `self-improving` agent after retros and during `/memory-review`
- It defines: read path, write path, file format, MEMORY.md template, temporal validity, checkpoints
- The file format (frontmatter with name, description, type, created, updated, valid_until, importance) stays unchanged
- The write targets (memory/, decisions/, context.md, retro.md) stay unchanged
- Only the READ PATH changes: knowledge graph → brief + files
- The provider config pointer section stays (tells agents not to write to ~/.claude/projects/etc)

## How

**Step 1 — Rewrite the Read vs Write section:**

Replace lines 12-23 (the read/write paths with knowledge graph branching) with:

```markdown
## Read vs Write Paths

```
READING memory:
  brief CLI available?
    YES → Use brief search, brief status, brief context
    NO  → Read MEMORY.md index + memory/ files directly

WRITING memory:
  ALWAYS write to structured files (memory/, decisions/, context.md, retro.md)
  These are the source of truth. brief indexes them automatically.
```
```

**Step 2 — Remove "Reading Memory (Knowledge Graph Available)" section:**

Delete lines 28-37 (the entire section with the MCP tools table: `knowledge_context`, `knowledge_search`, `knowledge_status`).

**Step 3 — Rename "Reading Memory (No Knowledge Graph)" to just "Reading Memory":**

Keep the content: "Read `MEMORY.md` for the index, then individual `memory/` files as needed."

Add brief commands above it:
```markdown
## Reading Memory

**Primary** — if `brief` CLI is installed:
```bash
brief search "<query>"          # search across all memory files
brief status                    # project state summary
brief context "<query>"         # search graduated context
```

**Fallback** — read files directly:
- `MEMORY.md` — lightweight index at project root
- `memory/*.md` — individual memory files
```

**Step 4 — Collapse MEMORY.md templates into one:**

Remove the "MEMORY.md Template (Knowledge Graph Projects)" section entirely (lines 114-134).

Rename "MEMORY.md Template (No Knowledge Graph)" to just "MEMORY.md Template" and keep its content:
```markdown
### MEMORY.md Template

```markdown
# Memory

One-line project orientation.

## Active Context
- [Current feature/work pointer]

## Durable Facts
- [topic](memory/type_topic.md) — one-line description
```
```

**Step 5 — Remove knowledge graph from Provider Config section:**

In the "Provider Config: Pointer Only" section (around line 200), remove the line:
```
- **Knowledge graph:** `.project/knowledge.db` (if set up)
```

**Step 6 — Remove knowledge graph from Rules section:**

Remove the rule: "Read from knowledge graph first — if `.project/knowledge.db` exists, use MCP tools for reads"

Replace with: "Read via `brief search` first — fall back to reading `memory/` files directly if brief is unavailable"

Also remove: "Files are the source of truth; the knowledge DB is a read index rebuilt from them"

**Step 7 — Remove any remaining references:**

Search for `knowledge` in the file and remove any remaining occurrences (line 9 in the description/frontmatter mentions "knowledge graph indexes these files").

Update frontmatter description to something like:
```
description: "Version-controlled project memory format. Auto-applies when something needs to be remembered, recalled, or written down for a future session. Defines where memory lives, how to read it, how to write it, and the file formats."
```
(This is already the current description — just verify no knowledge ref is in it.)
