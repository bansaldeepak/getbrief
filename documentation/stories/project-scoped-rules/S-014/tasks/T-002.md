# S-014-T2: Create scaffold-module Skill

**Priority:** P1 | **Status:** completed | **Blocked By:** --

## What
Create a generic module scaffolding skill at `skills/brief/scaffold-module/SKILL.md` and add a route entry in the brief router (`skills/brief/SKILL.md`). This replaces the Hono-specific `templates/project-skills/hono-new-module/SKILL.md` with a framework-agnostic version.

## Why
The existing `hono-new-module` skill is Hono-specific and has no installation path (it lives in `templates/project-skills/` which `brief init` never processes). A generic scaffold-module skill works for any framework and is routable through the brief lifecycle.

## Context
The brief router at `skills/brief/SKILL.md` has a Lifecycle Phases table and a Project Management Actions table. scaffold-module should go in the Project Management Actions table since it's an operational action, not a lifecycle phase.

The skill reads `techstack.md` (from `.claude/rules/techstack.md`) if present to understand the project's stack, then falls back to language defaults if not. It's a markdown instruction skill — the AI agent reads it and generates the scaffold, rather than running code. This matches how other brief skills work.

CEO review decided: built-in language defaults as fallback (not "refuse if no techstack.md"). The skill should work even before `brief init` runs.

## How

**Step 1 -- Create the skill file:**
- File: `skills/brief/scaffold-module/SKILL.md`
- Content:

```markdown
---
name: scaffold-module
description: "Scaffold a new module in the project. Reads techstack.md for conventions, falls back to language defaults."
user_invocable: true
argument-hint: "<module-name>"
---

# /brief scaffold-module -- Module Scaffold

Creates a new module directory with conventional file structure.

## Instructions

### Step 1: Detect Stack

Check for `.claude/rules/techstack.md` in the project root. If present, read it to determine:
- Language and framework (Stack section)
- Directory structure convention (Structure section)
- Path aliases (Aliases section)

If not present, detect from project files:
- `package.json` exists → Node.js/TypeScript (create: index.ts, service.ts, schemas.ts, __tests__/)
- `pyproject.toml` exists → Python (create: __init__.py, service.py, schemas.py, tests/)
- `Cargo.toml` exists → Rust (create: mod.rs, tests.rs)
- `go.mod` exists → Go (create: handler.go, service.go, handler_test.go)
- None detected → ask the user what language/framework to use

### Step 2: Determine Location

Ask the user where to create the module if not obvious from the argument:
- If techstack.md specifies a structure pattern (e.g., `app/server/modules/<name>/`), suggest that path
- Otherwise, suggest a reasonable default based on detected framework

### Step 3: Create Files

For each file in the module template:
1. Create the directory: `mkdir -p <module-path>`
2. Create each file with minimal boilerplate appropriate to the framework
3. If the framework uses barrel exports (index.ts/index.py), create one that re-exports from the other files

### Step 4: Report

List created files and suggest next steps:
- "Module created at <path>. Add routes/endpoints and implement service logic."
- If tests directory created: "Test file ready at <test-path>."

## Rules

- Never overwrite existing files
- Always create a test file alongside the module
- Follow the project's naming conventions from techstack.md or coding-style.md
- Ask before creating if the target directory already exists
```

**Step 2 -- Add router entry:**
- File: `skills/brief/SKILL.md`
- In the "Project Management Actions" table, add a new row after `verify`:

```markdown
| `scaffold-module` | Scaffold a new module directory with conventional file structure |
```

- Also add to the inline instructions section after `/brief verify`:

```markdown
For `scaffold-module`: read `skills/brief/scaffold-module/SKILL.md` and follow it.
```

Specifically, find this line in SKILL.md:
```
For `setup`, `migrate`, and `verify`: follow the instructions inline below (no separate file).
```
And change it to:
```
For `setup`, `migrate`, `verify`, and `scaffold-module`: `setup`/`migrate`/`verify` follow the instructions inline below; `scaffold-module` reads its own skill file.
```

**Step 3 -- Verify:**
```bash
test -f skills/brief/scaffold-module/SKILL.md && echo "skill exists" || echo "MISSING"
grep "scaffold-module" skills/brief/SKILL.md
node --test
```
