# S-014-T1: Create techstack.md Rule Template

**Priority:** P1 | **Status:** completed | **Blocked By:** --

## What
Create a new rule template `templates/rules/techstack.md` with brief:auto markers and add its entry to `templates/rules/manifest.json`. This rule captures project-specific tech stack configuration (language, runtime, aliases, directory structure) and installs on every project (detect: ["*"]).

## Why
The Hono-specific conventions in `templates/project-skills/hono-react-router-prisma/SKILL.md` mix two concerns: framework-specific route idioms (which belong in backend-standards) and stack configuration (which every project needs). techstack.md extracts the narrow, universal part so every project gets a place to document its stack.

## Context
Existing rule templates use `<!-- brief:auto section="name" -->` markers that `/brief init` fills. See `templates/rules/coding-style.md` for the pattern:

```markdown
---
description: Project-specific coding conventions. Refined by retro findings.
---

## Naming
<!-- brief:auto section="naming" -->
<!-- Example: Boolean variables prefixed with is/has/should. -->
<!-- /brief:auto -->
```

The manifest.json currently has 11 templates. techstack.md will be entry 12 with `detect: ["*"]` (always installed, since every project has a tech stack). The scope is narrow: stack list, runtime config, path aliases, directory structure. Route idioms and framework patterns stay in backend-standards/frontend-standards.

CEO review decided: detect any language/runtime, not just frameworks. Narrow scope (config only, not a kitchen-sink).

## How

**Step 1 -- Create the template file:**
- File: `templates/rules/techstack.md`
- Content:

```markdown
---
description: Tech stack, runtime config, path aliases, and directory structure.
---

## Stack
<!-- brief:auto section="stack" -->
<!-- Example: Node.js 20, TypeScript 5.x, Hono, React Router, Prisma ORM -->
<!-- /brief:auto -->

## Runtime & Config
<!-- brief:auto section="runtime" -->
<!-- Example: Cloudflare Workers (wrangler.toml), env vars in .dev.vars -->
<!-- /brief:auto -->

## Aliases
<!-- brief:auto section="aliases" -->
<!-- Example: @backend/* → app/server/, @frontend/* → app/client/ -->
<!-- /brief:auto -->

## Structure
<!-- brief:auto section="structure" -->
<!-- Example: app/server/modules/<name>/ with routes.ts, service.ts, schemas.ts -->
<!-- /brief:auto -->
```

**Step 2 -- Add manifest entry:**
- File: `templates/rules/manifest.json`
- Add this entry to the `templates` array (after safe-modifications, before the closing `]`):

```json
{
  "id": "techstack",
  "name": "Tech Stack",
  "description": "Tech stack, runtime config, path aliases, and directory structure",
  "detect": ["*"],
  "paths": [],
  "file": "techstack.md"
}
```

**Step 3 -- Verify:**
```bash
node -e "const m = JSON.parse(require('fs').readFileSync('templates/rules/manifest.json','utf8')); console.log(m.templates.length, 'templates'); const t = m.templates.find(t => t.id === 'techstack'); console.log(t ? 'techstack found' : 'MISSING')"
node --test
```
