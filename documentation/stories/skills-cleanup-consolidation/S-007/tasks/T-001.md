# S-007-T1: Create 4 New Rule Files

**Priority:** P0 | **Status:** completed | **Blocked By:** --

## What

Create 4 new rule files in `~/.agents/rules/` by extracting core principles from existing skills:
- `coding-standards.md` — from `custom-skills/coding-standards/SKILL.md` (174 lines → ~60 lines)
- `documentation-standards.md` — from `custom-skills/documentation-standards/SKILL.md`
- `observability.md` — from `custom-skills/observability/SKILL.md` (121 lines → ~40 lines)
- `git-workflow.md` — from AGENTS.md §"Git Branch & Push Safety" + §"Commit Convention"

## Why

These skills load only their description per session (not full content). Converting to rules means their content auto-loads when relevant files are touched (via `paths:` frontmatter). This gives agents immediate access to standards without explicit skill invocation.

## Context

**Current state:**
- `custom-skills/coding-standards/SKILL.md` (174 lines) — covers modularity, file-size limits, naming, testing, error handling, logging, dependencies
- `custom-skills/documentation-standards/SKILL.md` — covers doc modularity, ordering, Mermaid, quality bar
- `custom-skills/observability/SKILL.md` (121 lines) — covers 4 signals, abstraction, initialization, failure isolation, flush
- AGENTS.md lines 39-59 — git branch/push safety + commit convention

**Rules format:** See existing `rules/agent-discipline.md` and `rules/brief.md` for examples. Rules have optional `paths:` frontmatter for conditional loading.

**Key design decisions (from TRD):**
- coding-standards: NO `paths:` glob (applies universally to all files)
- documentation-standards: `paths: ["documentation/**", "*.md"]`
- observability: `paths:` TBD based on content (probably no glob — principles are universal)
- git-workflow: NO glob (applies whenever committing/pushing)

**What to extract vs. leave behind:**
- EXTRACT: Universal principles, limits, rules that apply regardless of project
- LEAVE BEHIND: Vendor-specific wiring (that goes to project-local templates in Story B), detailed examples (too long for rules)

## How

**Step 1 — Create `rules/coding-standards.md`:**
- File: `rules/coding-standards.md`
- Source: Read `custom-skills/coding-standards/SKILL.md` fully
- Extract: §1 Modularity (file-size table + function limits), §naming conventions, §type safety principles, §error handling principles
- Keep it under ~60 lines. No `paths:` frontmatter (universal).
- Format:
```markdown
---
description: Language-agnostic coding standards — modularity, file-size limits, naming, type safety, error handling.
---

# Coding Standards

## Modularity & File Size
<extract table + function limits>

## Naming & Type Safety
<extract principles only, not examples>

## Error Handling
<extract principles>
```

**Step 2 — Create `rules/documentation-standards.md`:**
- File: `rules/documentation-standards.md`
- Source: Read `custom-skills/documentation-standards/SKILL.md` fully
- Extract: Modularity rules, ordering rules, Mermaid principles, quality bar
- Add `paths:` frontmatter.
- Format:
```markdown
---
description: Documentation writing standards — modularity, ordering, diagrams, quality bar.
paths:
  - "documentation/**"
  - "*.md"
---

# Documentation Standards
<extracted principles, ~40-50 lines>
```

**Step 3 — Create `rules/observability.md`:**
- File: `rules/observability.md`
- Source: Read `custom-skills/observability/SKILL.md` fully
- Extract: The 4 signals table, abstraction principle, init boundary rule, failure isolation rule, flush semantics
- Leave behind: Vendor-specific examples, detailed patterns (those go to `observability-wiring.md` template in Story B)
- Keep under ~40 lines. No `paths:` (principles are universal).

**Step 4 — Create `rules/git-workflow.md`:**
- File: `rules/git-workflow.md`
- Source: AGENTS.md lines 39-59 (§"Git Branch & Push Safety" + §"Commit Convention")
- Extract: Branch naming, push safety, commit convention, the "never commit to main" rules
- No `paths:` (applies whenever committing).

**Step 5 — Verify:**
```bash
wc -l rules/coding-standards.md rules/documentation-standards.md rules/observability.md rules/git-workflow.md
# All should be under 60-70 lines each
grep -l "^paths:" rules/*.md
# Should show documentation-standards.md
```
