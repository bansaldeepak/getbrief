# S-004-T2: Log stores full body below frontmatter

**Status:** in_progress
**Priority:** P1
**Blocked By:** S-004-T1

## Description

Update logAdd to write multi-line body after --- when body provided via readBody()

## Implementation Notes

**File:** `brief/lib/commands/log.mjs` — `logAdd()`

- Import `readBody` from `../body.mjs`
- Make `logAdd` async, call `const body = await readBody(rawArgs)`
- Current template writes only frontmatter. Change: if body is non-null, append `\n${body.trim()}\n` after the closing `---`
- `note:` field stays as the short message arg (first positional arg, unchanged)
- Make `logCommand` async in `cli.mjs` (add await at call site)

Current format → new format:
```
---                          ---
note: short message          note: short message
---                          ---
                             
                             Full body content here.
                             Multiple lines supported.
```

## Verification

- [ ] `echo "detailed text" | brief log "summary"` → file has body below frontmatter
- [ ] `brief log "just a note"` (no pipe) → file is frontmatter-only (backward compat)
- [ ] `brief log "note" --body="inline body"` → file has body from flag
- [ ] `brief log show <file>` displays both frontmatter and body
