# S-004-T4: Story and task create accept body content

**Status:** pending
**Priority:** P1
**Blocked By:** S-004-T1

## Description

Update storyCreate and storyTaskCreate to inject body into Context/Description sections

## Implementation Notes

**File:** `brief/lib/commands/story.mjs` — `storyCreate()` and `storyTaskCreate()`

- Import `readBody` from `../body.mjs`
- Make both functions async, call `const body = await readBody(rawArgs)`

**storyCreate:**
- Template has `${opts.description || "<!-- Why this work is needed -->"}` for Context section
- Change: if body provided, use body as the Context content (overrides `--description` for full content)
- If both `--description` and `--body`: body wins (description is the short version for tracker, body is the full markdown)

**storyTaskCreate:**
- Template has `${description || "<!-- What this task accomplishes -->"}` for Description section
- Change: if body provided, use body as Description content (overrides `--description`)

- Make `storyCommand` async where needed, update routing

## Verification

- [ ] `brief story create "Test" --body="Full context paragraph explaining the need"` → Context section has body
- [ ] `echo "Task details" | brief story task create S-004 "Test task"` → Description section filled
- [ ] `brief story create "No body"` → still has `<!-- ... -->` (backward compat)
- [ ] `--description="short" --body="long"` → body wins in file, description may still go to tracker
