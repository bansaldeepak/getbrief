# S-011-T8: Migration Detection — Old Path Auto-Update

**Priority:** P2 | **Status:** completed | **Blocked By:** S-011-T4

## What
Add migration detection to `init.mjs` that finds old `custom-skills/` symlinks in projects and automatically updates them to point to the new `~/.agents/brief/skills/brief/` location. This handles the transition for any project that was previously initialized before T1's relocation.

## Why
After T1 moves skills from `custom-skills/` to `brief/skills/`, any project that previously ran `brief init` (or manually symlinked to `custom-skills/`) will have broken or stale symlinks. Rather than requiring users to manually find and fix these, init detects old-path patterns and auto-updates them during re-init.

## Context
**Old symlink patterns to detect:**
```
# These pointed to the old location
.claude/skills/brief   → ~/.agents/custom-skills/brief
.claude/skills/sdlc    → ~/.agents/custom-skills/sdlc
.agents/skills/brief   → ~/.agents/custom-skills/brief
.agents/skills/sdlc    → ~/.agents/custom-skills/sdlc
```

**New targets after migration:**
```
.claude/skills/brief   → ~/.agents/brief/skills/brief
.agents/skills/brief   → ~/.agents/brief/skills/brief
# sdlc no longer gets its own project symlink — it's a sub-skill of brief
```

**Detection strategy:**
1. During init, before creating new symlinks, check if existing symlinks point to paths containing `custom-skills/`
2. If found: remove old symlink, create new one pointing to `~/.agents/brief/skills/brief/`
3. Report the migration: "Migrated: .claude/skills/brief (old path → new path)"

**Edge cases:**
- Old symlink target doesn't exist anymore (custom-skills/ already deleted by T1) → still a broken symlink, remove it
- Project has manual symlinks to some other location (not custom-skills/) → leave alone
- Project never had symlinks (fresh project) → nothing to migrate
- Multiple old symlinks (brief + sdlc + project-memory) → migrate brief, remove sdlc/project-memory symlinks (they're now sub-skills)

**Where in init flow:**
Insert migration check between "detect agents" (step 3) and "create new symlinks" (step 5). This way old links are cleaned before new ones are created, and `createLink` won't see stale EEXIST.

## How

**Step 1 -- Add migration function to init.mjs:**

```javascript
import { readlinkSync, lstatSync, rmSync } from "node:fs";
import { join } from "node:path";
import { homedir } from "node:os";

const OLD_PATH_PATTERN = /custom-skills/;
const OLD_SYMLINKS_TO_REMOVE = ["sdlc", "project-memory"]; // No longer separate project symlinks

function migrateOldSymlinks(projectRoot) {
  const migrated = [];
  const removed = [];
  const home = homedir();

  const linksToCheck = [
    { dir: ".claude/skills", name: "brief" },
    { dir: ".claude/skills", name: "sdlc" },
    { dir: ".claude/skills", name: "project-memory" },
    { dir: ".agents/skills", name: "brief" },
    { dir: ".agents/skills", name: "sdlc" },
    { dir: ".agents/skills", name: "project-memory" },
  ];

  for (const { dir, name } of linksToCheck) {
    const linkPath = join(projectRoot, dir, name);
    const target = safeReadlink(linkPath);
    if (!target) continue; // Not a symlink or doesn't exist

    const isOldPath = OLD_PATH_PATTERN.test(target);
    if (!isOldPath) continue; // Not an old-style link

    // Remove the old symlink
    rmSync(linkPath);

    if (OLD_SYMLINKS_TO_REMOVE.includes(name)) {
      // sdlc and project-memory are now sub-skills — don't recreate
      removed.push({ path: `${dir}/${name}`, oldTarget: target, action: "removed" });
    } else {
      // brief → recreate with new target (handled by createProjectSymlinks later)
      migrated.push({ path: `${dir}/${name}`, oldTarget: target, action: "migrated" });
    }
  }

  return { migrated, removed };
}

function safeReadlink(p) {
  try {
    const stat = lstatSync(p);
    if (stat.isSymbolicLink()) return readlinkSync(p);
    return null;
  } catch { return null; }
}
```

**Step 2 -- Integrate into init flow:**
In the rewritten `initProject` (from T4), add between detection and symlink creation:

```javascript
// Between step 3 (detect) and step 5 (symlinks):
const migration = migrateOldSymlinks(projectRoot);
if (migration.migrated.length || migration.removed.length) {
  console.log("Migrated old symlinks:");
  for (const m of migration.migrated) {
    console.log(`  ↻ ${m.path} (updated to new location)`);
  }
  for (const r of migration.removed) {
    console.log(`  ✗ ${r.path} (removed — now a sub-skill of /brief)`);
  }
}
```

**Step 3 -- Write integration test:**
- File: `~/.agents/brief/test/migration.test.mjs`
- Test cases:
  - Project with old `custom-skills/` symlinks → detected and removed
  - Old `brief` symlink → removed (new one created by subsequent createProjectSymlinks step)
  - Old `sdlc` symlink → removed permanently (not recreated)
  - Old `project-memory` symlink → removed permanently (not recreated)
  - Project with no symlinks → no migration actions
  - Project with non-custom-skills symlinks → left untouched
  - Broken old symlink (target already gone) → still detected and removed
