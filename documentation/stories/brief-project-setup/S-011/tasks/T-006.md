# S-011-T6: /brief init Skill — Agent-Driven Rule Content Fill

**Priority:** P1 | **Status:** pending | **Blocked By:** S-011-T5

## What
Create the `/brief init` agent skill at `~/.agents/brief/skills/brief/init/SKILL.md`. This is an AI-powered skill that reads the project codebase, infers conventions, and fills content inside the marker sections placed by T5's `rules-gen.mjs`. It also includes a marker parser module for the merge algorithm.

## Why
T5 places empty containers (markers with placeholder text). The agent skill reads actual code to fill those containers with real project conventions — things like "use ESM imports", "prefer Hono's `c.json()` over raw Response", "tests use vitest with describe/it pattern". This is the step that makes rules useful rather than empty skeletons. The marker-based merge ensures re-running the skill updates generated content without destroying manual edits.

## Context
**Interface between T5 and T6:**
- T5 creates files with markers: `<!-- brief:auto section="X" -->...(placeholder)...<!-- /brief:auto -->`
- T6 (this skill) replaces content between markers with real inferred conventions
- Content outside markers is never touched

**Marker merge algorithm (from TRD):**
```
parseFile(content):
  sections = []
  for each <!-- brief:auto --> ... <!-- /brief:auto --> pair:
    sections.push({ type: 'manual', content: before_marker })
    sections.push({ type: 'auto', id: section_attr, content: inner })
  sections.push({ type: 'manual', content: after_last_marker })
  return sections

merge(existing_sections, new_generated):
  for each section in existing_sections:
    if section.type == 'manual': keep as-is
    if section.type == 'auto' and new_generated has section.id:
      replace content, update timestamp
  for each new section not in existing:
    append at end
```

**What the agent infers (hardcoded list initially):**
- **Naming conventions**: camelCase vs snake_case, file naming patterns
- **Import style**: ESM vs CommonJS, path aliases, barrel exports
- **Testing patterns**: test runner, describe/it vs test(), assertion style
- **Framework idioms**: Hono handlers, Prisma patterns, React hooks
- **Error handling**: typed errors, Result patterns, try/catch conventions

**Negative test cases for marker parser (from TRD):**
- Nested `<!-- brief:auto -->` inside another → error, skip file
- Unclosed marker (no `<!-- /brief:auto -->`) → error, skip file
- Markers inside triple-backtick code blocks → ignore (not real markers)
- Empty section between markers → valid (agent will fill)
- Duplicate section names → last wins

**Per-agent output format:**
- Claude: preserve frontmatter above markers, fill conventions inside
- Codex: fill the AGENTS.md section (keep it concise, <2KB)
- Gemini: fill plain md markers

## How

**Step 1 -- Create the marker parser module:**
- File: `~/.agents/brief/lib/markers.mjs`

```javascript
const OPEN_RE = /^<!-- brief:auto section="([^"]+)"(?: generated="[^"]*")? -->\s*$/;
const CLOSE_RE = /^<!-- \/brief:auto -->\s*$/;

export function parseMarkers(content) {
  const lines = content.split("\n");
  const sections = [];
  let i = 0;
  let manualStart = 0;
  let inCodeBlock = false;

  while (i < lines.length) {
    // Track code blocks (markers inside ``` are not real)
    if (lines[i].startsWith("```")) {
      inCodeBlock = !inCodeBlock;
      i++;
      continue;
    }
    if (inCodeBlock) { i++; continue; }

    const openMatch = lines[i].match(OPEN_RE);
    if (openMatch) {
      // Push manual section before this marker
      if (i > manualStart) {
        sections.push({ type: "manual", content: lines.slice(manualStart, i).join("\n") });
      }
      const sectionId = openMatch[1];
      const startLine = i;
      i++;
      // Find closing marker
      let found = false;
      while (i < lines.length) {
        if (lines[i].startsWith("```")) { inCodeBlock = !inCodeBlock; i++; continue; }
        if (inCodeBlock) { i++; continue; }
        if (CLOSE_RE.test(lines[i])) {
          sections.push({ type: "auto", id: sectionId, content: lines.slice(startLine + 1, i).join("\n") });
          manualStart = i + 1;
          found = true;
          i++;
          break;
        }
        // Check for nested open (error case)
        if (OPEN_RE.test(lines[i])) {
          throw new Error(`Nested marker at line ${i + 1}: cannot have <!-- brief:auto --> inside another`);
        }
        i++;
      }
      if (!found) {
        throw new Error(`Unclosed marker for section "${sectionId}" starting at line ${startLine + 1}`);
      }
    } else {
      i++;
    }
  }
  // Trailing manual content
  if (manualStart < lines.length) {
    sections.push({ type: "manual", content: lines.slice(manualStart).join("\n") });
  }
  return sections;
}

export function mergeContent(sections, newGenerated) {
  const ts = new Date().toISOString();
  const result = [];
  const usedSections = new Set();

  for (const section of sections) {
    if (section.type === "manual") {
      result.push(section.content);
    } else if (section.type === "auto") {
      usedSections.add(section.id);
      const newContent = newGenerated[section.id];
      if (newContent !== undefined) {
        result.push(`<!-- brief:auto section="${section.id}" generated="${ts}" -->`);
        result.push(newContent);
        result.push(`<!-- /brief:auto -->`);
      } else {
        // Keep existing auto content if no new content provided
        result.push(`<!-- brief:auto section="${section.id}" generated="${ts}" -->`);
        result.push(section.content);
        result.push(`<!-- /brief:auto -->`);
      }
    }
  }

  // Append new sections not in existing
  for (const [id, content] of Object.entries(newGenerated)) {
    if (!usedSections.has(id)) {
      result.push("");
      result.push(`<!-- brief:auto section="${id}" generated="${ts}" -->`);
      result.push(content);
      result.push(`<!-- /brief:auto -->`);
    }
  }

  return result.join("\n");
}
```

# /brief init — Fill Rule Skeletons with Project Conventions

## When to Use
After running `brief init` (CLI) which creates rule files with empty markers. This skill reads your code and fills those markers with real conventions.

## Instructions

### Step 1: Verify Brief is Installed
Check `.agents/brief-manifest.json` exists. If not: "Run `brief init` first to scaffold the project."

### Step 2: Detect What's Present
Read the manifest to understand:
- Which agents are configured (detection.agents)
- Which rules were installed (rules_installed)
- What tech stack was detected (detection.frameworks, detection.languages)

### Step 3: Read Project Code
Based on detected stack, read representative files:
- `package.json` — deps, scripts, type field
- `tsconfig.json` — compiler options, paths
- 3-5 source files from `src/` — naming, import style, patterns
- 1-2 test files — test runner, assertion patterns
- `.eslintrc*` or `biome.json` — linting rules already defined

### Step 4: Infer Conventions
From the code, determine:
- **Naming**: camelCase/snake_case for functions, PascalCase for types, file naming
- **Imports**: ESM/CJS, path aliases, barrel patterns
- **Testing**: runner (vitest/jest/mocha), pattern (describe/it vs test), mocking approach
- **Framework**: specific idioms (Hono c.json(), Prisma patterns, React hooks)
- **Error handling**: typed errors, Result<T,E>, try/catch patterns
- **Architecture**: layer patterns (handlers→services→providers), module boundaries

### Step 5: Fill Each Rule File
For each rule file listed in the manifest:

1. Read the file
2. Parse markers (use the algorithm above)
3. Generate convention content for each `section` found
4. Merge: replace auto sections, preserve manual sections
5. Write back

**Per-agent format awareness:**
- `.claude/rules/*.md` — keep frontmatter intact, fill after it
- `AGENTS.md` — keep concise (<2KB for brief section), conventions only
- `.agents/rules/*.md` — fill directly (plain md)

### Step 6: Report
Print what was filled/updated per agent. Example:
```
Filled rules:
  .claude/rules/coding-style.md — 8 conventions inferred
  .claude/rules/backend-standards.md — 5 framework patterns
  AGENTS.md — conventions section added (1.2KB)
  .agents/rules/coding-style.md — mirrored from Claude rules
```

## Rules
- Never modify content outside `<!-- brief:auto -->` markers
- If markers are corrupted (nested, unclosed): skip that file, warn user
- Keep generated content concise — bullet points, not essays
- Use present tense imperatives ("Use ESM imports", not "The project uses ESM imports")
- If you can't infer something confidently, omit it rather than guessing
- Re-running must be safe: only marker content changes, everything else preserved
```
