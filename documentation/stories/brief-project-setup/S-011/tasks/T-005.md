# S-011-T5: rules-gen.mjs — Per-Agent Rule Format Scaffolder

**Priority:** P1 | **Status:** pending | **Blocked By:** --

## What
Create `~/.agents/brief/lib/rules-gen.mjs` that generates rule skeleton files in each detected agent's native format. It places the container files with correct format (Claude frontmatter + markers, Codex AGENTS.md section + markers, Gemini plain md + markers) — but does NOT fill content. Content filling is done by the `/brief init` agent skill (T6).

## Why
Each agent reads rules differently:
- **Claude**: `.claude/rules/*.md` with YAML frontmatter (`paths:` globs)
- **Codex**: `AGENTS.md` (single markdown file, concatenated per-dir, 32KB cap)
- **Gemini**: `.agents/rules/*.md` (plain markdown, no frontmatter)

The same conventions need to exist in all three formats. T5 creates the structural containers with markers; T6 fills the content. This separation means: T5 is a pure CLI function (deterministic), T6 is an AI-powered skill (reads code, infers conventions). The interface between them is the marker format.

## Context
**Marker format (from TRD):**
```markdown
<!-- brief:auto section="coding-style" generated="2026-08-25T10:00:00Z" -->
## Generated: Coding Style

(content will be filled by /brief init skill)

<!-- /brief:auto -->
```

**Claude format** (`.claude/rules/coding-standards.md`):
```markdown
---
paths:
  - "src/**/*.ts"
  - "lib/**/*.mjs"
---
<!-- brief:auto section="conventions" -->
## Conventions

(filled by /brief init)

<!-- /brief:auto -->
```

**Codex format** (`AGENTS.md` — append section):
```markdown
<!-- brief:auto section="conventions" -->
## Coding Conventions (managed by brief)

(filled by /brief init)

<!-- /brief:auto -->
```

**Gemini format** (`.agents/rules/coding-standards.md`):
```markdown
<!-- brief:auto section="conventions" -->
## Conventions

(filled by /brief init)

<!-- /brief:auto -->
```

**AGENTS.md 32KB cap (TRD decision):**
Before appending to AGENTS.md, read current file size. If current + estimated new content > 30KB: warn and skip Codex rule generation. Brief's marker section should be concise (conventions only, target <2KB).

**Existing rule templates** (`~/.agents/brief/templates/rules/`):
```
backend-standards.md, coding-style.md, deployment.md,
frontend-standards.md, git-workflow.md, manifest.json,
observability-wiring.md, product-analytics.md
```

These are currently plain markdown skeletons (no frontmatter, no markers). T5 uses them as the content base but wraps output in the correct per-agent format.

## How

**Step 1 -- Create the file:**
- File: `~/.agents/brief/lib/rules-gen.mjs`

```javascript
import { existsSync, readFileSync, writeFileSync, statSync, mkdirSync } from "node:fs";
import { join } from "node:path";

const MARKER_OPEN = (section, ts) =>
  `<!-- brief:auto section="${section}" generated="${ts}" -->`;
const MARKER_CLOSE = `<!-- /brief:auto -->`;

export function generateRuleSkeletons(projectRoot, detection, selectedRules) {
  const results = { claude: [], codex: [], gemini: [] };
  const ts = new Date().toISOString();

  if (detection.agents.claude) {
    results.claude = generateClaudeRules(projectRoot, selectedRules, ts);
  }
  if (detection.agents.codex) {
    results.codex = generateCodexSection(projectRoot, selectedRules, ts);
  }
  if (detection.agents.gemini) {
    results.gemini = generateGeminiRules(projectRoot, selectedRules, ts);
  }

  return results;
}
```

**Step 2 -- Implement `generateClaudeRules`:**
For each selected rule template:
- Check if `.claude/rules/<name>.md` already has markers → skip (don't overwrite)
- If file exists without markers → append markers at end (preserve existing content)
- If file doesn't exist → create with frontmatter + markers

```javascript
function generateClaudeRules(projectRoot, rules, ts) {
  const rulesDir = join(projectRoot, ".claude", "rules");
  mkdirSync(rulesDir, { recursive: true });
  const created = [];

  for (const rule of rules) {
    const filePath = join(rulesDir, rule.file);
    if (existsSync(filePath)) {
      const content = readFileSync(filePath, "utf8");
      if (content.includes("brief:auto")) continue; // already has markers
      // Append markers to existing file
      const appended = content + "\n\n" + MARKER_OPEN(rule.id, ts) + "\n" +
        `## Generated: ${rule.name}\n\n(filled by /brief init)\n\n` + MARKER_CLOSE + "\n";
      writeFileSync(filePath, appended);
      created.push({ file: rule.file, action: "appended-markers" });
    } else {
      // Create new with frontmatter
      const frontmatter = rule.paths?.length
        ? `---\npaths:\n${rule.paths.map(p => `  - "${p}"`).join("\n")}\n---\n`
        : `---\npaths:\n  - "**/*"\n---\n`;
      const content = frontmatter + "\n" + MARKER_OPEN(rule.id, ts) + "\n" +
        `## Generated: ${rule.name}\n\n(filled by /brief init)\n\n` + MARKER_CLOSE + "\n";
      writeFileSync(filePath, content);
      created.push({ file: rule.file, action: "created" });
    }
  }
  return created;
}
```

**Step 3 -- Implement `generateCodexSection`:**
```javascript
function generateCodexSection(projectRoot, rules, ts) {
  const agentsPath = join(projectRoot, "AGENTS.md");
  const maxSize = 30 * 1024; // 30KB threshold (32KB cap with buffer)

  let content = existsSync(agentsPath) ? readFileSync(agentsPath, "utf8") : "";

  // Check size
  if (content.length > maxSize) {
    console.warn("Warning: AGENTS.md exceeds 30KB. Skipping brief conventions for Codex.");
    return [{ file: "AGENTS.md", action: "skipped-size-cap" }];
  }

  // Check if markers already exist
  if (content.includes("brief:auto")) {
    return [{ file: "AGENTS.md", action: "already-has-markers" }];
  }

  // Append section
  const section = "\n\n" + MARKER_OPEN("conventions", ts) + "\n" +
    "## Coding Conventions (managed by brief)\n\n" +
    "(filled by /brief init)\n\n" + MARKER_CLOSE + "\n";
  writeFileSync(agentsPath, content + section);
  return [{ file: "AGENTS.md", action: "appended" }];
}
```
