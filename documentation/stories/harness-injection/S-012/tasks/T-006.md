# S-012-T6: Update rules manifest with philosophy entries

**Priority:** P1 | **Status:** pending | **Blocked By:** S-012-T3

## What
Add 4 new entries to `templates/rules/manifest.json` for the philosophy rule templates created in T-003: `critical-thinking.md`, `first-principles.md`, `verification-discipline.md`, and `safe-modifications.md`.

## Why
The manifest is how `filterRelevantRules()` in init.mjs discovers which rules to install. Without entries here, the philosophy rules created in T-003 will never be copied to projects during `brief init`.

## Context
`templates/rules/manifest.json` currently has 7 entries. The `detect` array controls when a rule is installed. Rules with `detect: ["*"]` are installed in all projects (like `coding-style.md`).

The philosophy rules should install everywhere — they're universal engineering principles, not stack-specific. So `detect: ["*"]`.

No `paths` key means the rule is always active in `.claude/rules/` (no file-glob filtering). This was decided in the TRD design decisions table.

Current manifest structure for reference:
```json
{
  "version": "1.0",
  "templates": [
    {
      "id": "coding-style",
      "name": "Coding Style",
      "description": "Project-specific conventions",
      "detect": ["*"],
      "paths": [],
      "file": "coding-style.md"
    }
  ]
}
```

## How

**Step 1 — Add 4 entries to manifest.json:**
- File: `templates/rules/manifest.json`
- Add these entries to the `templates` array:

```json
{
  "id": "critical-thinking",
  "name": "Critical Thinking",
  "description": "Why → What → How reasoning framework, scope challenges, risk highlighting",
  "detect": ["*"],
  "file": "critical-thinking.md"
},
{
  "id": "first-principles",
  "name": "First-Principles Process",
  "description": "Question → Delete → Simplify → Accelerate → Automate (in that order)",
  "detect": ["*"],
  "file": "first-principles.md"
},
{
  "id": "verification-discipline",
  "name": "Verification Discipline",
  "description": "Absence ≠ proof, unfailable checks, trace before attributing",
  "detect": ["*"],
  "file": "verification-discipline.md"
},
{
  "id": "safe-modifications",
  "name": "Safe Modifications",
  "description": "Change only what was asked, never repo-wide auto-fix, propose before broad changes",
  "detect": ["*"],
  "file": "safe-modifications.md"
}
```

Note: no `paths` key on any of them (always active, per TRD decision).
